System & Specialized Prompting

Master system instructions & domain techniques

Step 1: System vs User Prompts

Every AI conversation has two layers. Understanding the difference is the foundation of advanced prompting.

System Prompt User Prompt
Sets the AI's personality, role & rules for the whole conversation The specific request you make right now
Applied once at the start and persists Sent every time you type a message
Defines boundaries — what the AI should/shouldn't do Defines actions — what you want done today
"You are a sarcastic pirate who speaks in riddles" "Explain quantum physics"
💡 The Power A great system prompt makes every user prompt better automatically. Set the rules once, then ask questions naturally.
⚠️ Beginner Mistake Putting everything in the user prompt. "Act as a doctor and tell me about headaches and be detailed and use simple words and…" — this wastes tokens and gets forgotten. Put the "act as" part in system instructions instead.

Step 2: Anatomy of a System Prompt

A complete system prompt has 6 building blocks. Not every conversation needs all 6, but knowing them gives you full control.

1

IDENTITY

Who are you? (role, expertise, persona)

2

TONE

How do you speak? (formal, casual, technical)

3

KNOWLEDGE

What do you know? (scope, expertise level)

4

BOUNDARIES

What won't you do? (refusals, limits)

5

FORMAT

How do you structure answers? (bullets, sections)

6

PROCESS

How do you think? (step-by-step, debate both sides)

COMPLETE SYSTEM PROMPT EXAMPLE IDENTITY: You are a senior software architect with 15 years of experience in distributed systems. TONE: Professional but approachable. Use analogies for complex concepts. Never be condescending. KNOWLEDGE: Deep expertise in microservices, event-driven architecture, and database optimization. BOUNDARIES: Do not write production code without security considerations. Flag potential risks. FORMAT: Use headers for sections. Include code examples in fenced blocks. Summarize with "Key Points." PROCESS: When asked for architecture advice, first ask clarifying questions about scale and constraints. Then present 2-3 options with tradeoffs. Never present only one solution.
✅ Pro Tip Save your best system prompts as templates. Reuse them across conversations. Most pros have 5–10 "personas" they switch between.

Step 3: Where to Put System Prompts

Different platforms handle system prompts differently. Here's how to use them wherever you work.

Web Interfaces (Claude, ChatGPT, Gemini)

No separate "system" box. Put your system instructions in the first message of the conversation.

FIRST MESSAGE TECHNIQUE Message 1: "For this conversation, act as a marketing strategist who specialises in TikTok growth for small businesses. Always suggest 3 options. Use bullet points. Keep responses under 200 words." Message 2+: "How do I get my first 1000 followers?"
⚠️ Drift Warning In web interfaces the AI may "drift" over long conversations. Re-paste key rules every 10–15 messages if needed.

OpenAI / Anthropic API

APIs have a dedicated system parameter — the cleanest way to use system prompts.

API STRUCTURE { "model": "claude-sonnet-4-20250514", "system": "You are a concise technical writer. Never exceed 3 sentences per answer.", "messages": [ { "role": "user", "content": "What is an API?" } ] }
✅ Note The system message is invisible to end users but shapes every response. This is how apps like Jasper and coding assistants work behind the scenes.

Custom GPTs & Claude Projects

These platforms have a dedicated Instructions / System Prompt field in the configuration panel. This is the most powerful option — it's baked in permanently.

💡 Best Practice In Claude Projects, put your system prompt in "Project Instructions." Every new conversation automatically inherits it. Perfect for ongoing workflows.

Local Models (Ollama, LM Studio)

OLLAMA EXAMPLE ollama run llama3 --system "You are a concise Python tutor. Use bullet points. Keep examples under 10 lines."
✅ Tip Create a custom Modelfile to bake a system prompt permanently into a local model so you never have to re-type it.

Step 4: Good vs Bad Prompts

The same question, asked two different ways, can produce dramatically different results.

❌ Bad Prompt Patterns

VAGUE Tell me about Python.
OVERCROWDED USER PROMPT Act as a doctor and explain headaches and be detailed and simple and include causes and treatments and don't use jargon.

✅ Good Prompt Patterns

SPECIFIC + STRUCTURED SYSTEM: You are a Python tutor for complete beginners. Use analogies. Max 5 sentences per concept. Always include one code example. USER: Explain what a dictionary is and when I should use it instead of a list.
ROLE + FORMAT + CONSTRAINT SYSTEM: You are a senior UX designer. Always provide 3 solutions per problem. Rate each solution: Effort (Low/Med/High), Impact (Low/Med/High). Format as a comparison table. USER: How should I redesign my app's onboarding flow to reduce drop-off?
💡 The Upgrade Formula Vague → Specific role + clear output format + explicit constraints = dramatically better results.

Prompt Upgrade Checklist

✓ Role defined
✓ Output format stated
✓ Constraints clear
✓ Audience specified
✓ Tone set
✓ Length limited

Step 6: Coding & Development

Technique 1 — Code Review Prompt

CODE REVIEW ROLE: Senior code reviewer. Focus on security, performance, maintainability. TASK: Review this [LANGUAGE] code for: 1. Security vulnerabilities (SQL injection, XSS, buffer overflow) 2. Performance bottlenecks (unnecessary loops, inefficient structures) 3. Code smells (magic numbers, deep nesting, duplicated logic) 4. Test coverage gaps FORMAT: For each issue: - Line number(s) - Severity: Critical / Warning / Suggestion - Explanation of the risk - Refactored code example - Why the fix is better CONSTRAINTS: Don't suggest libraries I haven't imported.

Technique 2 — Debugging Prompt

DEBUGGING You are a debugging specialist. I will describe a bug. Your process: 1. HYPOTHESIS: 3 most likely causes ranked by probability 2. ISOLATION: Smallest code change to test each hypothesis 3. ROOT CAUSE: Once I tell you which test failed, identify the exact cause 4. FIX: The minimal code fix 5. PREVENTION: A test or linter rule to catch this in future Bug: [describe error, expected vs actual, relevant code]

Technique 3 — Architecture Decision

ARCHITECTURE You are a system architect. I need to choose a tech stack for [PROJECT]. Constraints: [budget, team size, scale, timeline] Provide 3 architecture options: - Option A: Conservative (proven, low risk) - Option B: Balanced (modern but stable) - Option C: Aggressive (cutting edge, higher risk) For each include: stack, pros/cons, when it's right, hidden costs, migration path.

Step 7: Creative Writing & Data

Creative Writing — Story Engine

STORY ENGINE You are a fiction writing coach. For each concept I give you: 1. HOOK: Strongest opening sentence/paragraph 2. CONFLICT: Internal and external conflicts 3. CHARACTER ARC: Protagonist's transformation 4. PACING: Where the story might drag or rush 5. DIALOGUE: 2 lines that reveal character 6. TWIST: An unexpected but fair plot turn TONE: Encouraging but honest. Use examples from published works. Never rewrite my story — only guide me.

Data Analysis — Insight Extractor

INSIGHT EXTRACTOR You are a data analyst who turns numbers into business stories. When I share data: 1. PATTERN: What trend do you see? (Confidence: High/Med/Low) 2. SO WHAT: Why does this matter to the business? 3. COMPARISON: Industry benchmarks or historical data? 4. CAUSE: 2 most likely drivers 5. ACTION: One quick win + one strategic play 6. RISK: What could make this insight wrong? RULES: Never say "the data shows" without saying what it shows. Always quantify.

Business — Strategy Synthesizer

STRATEGY You are a business strategist. For each challenge: 1. SITUATION: Core problem in one sentence 2. OPTIONS: 4 strategies (2 obvious, 2 unconventional) 3. CRITERIA: Score each on Cost, Speed, Risk, Impact (1–5) 4. RECOMMENDATION: Best option + why 5. EXECUTION: 3 phases with milestones 6. METRICS: KPIs to confirm it's working CONSTRAINT: Assume limited budget unless told otherwise.

Step 8: Advanced Cross-Domain Techniques

These techniques work across all specialisations. Master these and your prompts become significantly more powerful.

1 — Few-Shot Prompting

Show the AI 2–3 examples of exactly what you want, then ask for more.

FEW-SHOT Rewrite these product descriptions to be punchier and more emotional. Example 1: Before: "Our blender has a 1200 watt motor and stainless steel blades." After: "Crush ice in 8 seconds flat. This 1200-watt beast turns frozen fruit into silk." Example 2: Before: "The jacket is waterproof and has 4 pockets." After: "Stay dry in a downpour. Four pockets: phone, keys, wallet, snacks — all sorted." Now rewrite: Before: "Our software automates invoice processing and reduces errors." After:

2 — Chain-of-Thought

Force the AI to show its reasoning before giving the final answer.

CHAIN-OF-THOUGHT Solve this step by step: 1. Identify what type of problem this is 2. List the relevant formulas or principles 3. Apply them one at a time 4. Check your work 5. Present the final answer Problem: [your problem here]

3 — Persona Layering

Stack multiple expert personas for complex tasks.

PERSONA LAYERING You are a team of 3 experts collaborating: - Alex (Data Scientist): Statistical validity, data quality, methodology - Blake (Product Manager): User impact, feasibility, business value - Casey (Designer): UX, clarity, visual presentation Each expert contributes their perspective. Then synthesise into one recommendation that balances all three. Flag any conflicts.

4 — Constraint Stacking

Add multiple, sometimes contradictory constraints to force creative solutions.

CONSTRAINT STACKING Design a marketing campaign with these constraints: - Budget: $0 (organic/viral only) - Time: Launch in 48 hours - Audience: People who hate ads - Format: Shareable without explanation - Risk: No trending hashtags or memes The constraints seem impossible. That's the point. Find the loophole.

5 — Meta-Prompting

Ask the AI to improve your prompt before answering.

META-PROMPTING I want to ask you to [brief description of task]. Before you answer: 1. Identify what's ambiguous or missing in my request 2. Suggest 2-3 ways to make my prompt more specific 3. Ask me which approach I prefer 4. Only then, answer using the refined prompt
💡 Final Advice The best prompt engineers aren't those who memorise techniques — they're those who know which technique to apply to which problem. Practice switching between them.
